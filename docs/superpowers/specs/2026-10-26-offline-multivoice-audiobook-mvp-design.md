# 离线多人有声小说 MVP 设计

## 目标

做一个仅在本机运行的 Windows 桌面工具，把中文 TXT 网文转换为使用不同音色的多人有声小说。

使用者导入 TXT 后，程序自动识别章节、拆分旁白和对白、从明确的说话提示中提取角色，并允许人工修正角色归属。用户为旁白和各角色选择内置音色后，可以按章节生成音频并导出 MP3。安装完成后，小说内容和声音均不离开本机，运行过程不依赖网络或付费服务。

本项目只供个人使用。

## 验收目标

MVP 完成后，选择一本结构正常的 TXT 网文，可以：

1. 正确识别常见章节标题并展示章节列表。
2. 区分旁白与中文引号中的对白，识别一部分有明确“某人说/问/道”提示的角色。
3. 在桌面界面中修正角色名称、对白归属和音色。
4. 使用至少 6 个不同中文内置音色生成旁白和角色对白。
5. 逐章或连续生成音频，显示进度，并允许重试失败章节。
6. 导出一个能够正常播放且时长合理的章节 MP3。
7. 关闭并重新打开程序后，保留项目、角色、音色、修改和已完成音频记录。

自动角色识别不要求一次完全正确。对白无法可靠归因时，必须标记为“未分配角色”，而不是静默选择错误声音。

## 范围

### 第一版包含

- Windows 桌面程序，中文界面。
- 导入 UTF-8、GBK、UTF-16 编码的 `.txt` 文件。
- 自动识别常见中文章节标题，并允许手动改名、拆分和合并章节。
- 将正文拆成旁白和对白片段。
- 根据同一段或相邻文本中的明确说话提示提取角色，例如“林舟说道”“她笑道”。“她/他”无法可靠消歧时保持未分配。
- 角色列表管理、音色选择、短句试听。
- 文本片段列表和说话人修改；支持将多个片段批量分配给同一角色。
- 按章节或整本生成，支持停止、继续和重试失败片段。
- 按“文本 + 音色 + 语速 + 模型版本”缓存音频，未变化的片段不重复生成。
- 每章导出一个 MP3，文件名为“序号 - 章节名.mp3”。
- 本地项目自动保存、异常退出恢复和基础日志。

### 第一版不包含

- EPUB、PDF、DOCX、HTML 和带 DRM 的电子书。
- 插图、封面、背景音乐、音效、混响和母带处理。
- 声音克隆、上传参考音频、音色训练。
- AI 情绪表演、逐句情绪标签和自动导演。
- 本地大语言模型角色推断。
- 云端 API、账号、同步、分享、支付和多人协作。
- 手机应用。
- 可安装的正式发行包和自动更新。

### 不应出现的结果

- 程序运行期间必须联网，或把小说文本发送到外部服务。
- 因为单段失败而丢失整本书的已生成结果。
- 未分配角色被随机分配声音却不提示。
- 修改一个角色音色后必须重新生成全部未受影响的音频。
- 只有开发者命令行才能完成任务；核心流程必须有桌面界面。

## 运行环境与约束

目标机器已经确认具备 Ryzen 9 8945HX、32 GB 内存、RTX 5060 Laptop 8 GB 显存和约 217 GB 可用空间。

MVP 默认使用 CPU 运行轻量 ONNX 中文 TTS，避免让第一版受 NVIDIA 驱动和 CUDA 动态库兼容问题阻塞。界面保留计算后端配置，但第一版只要求 CPU 模式通过验收；GPU 优化作为后续工作。

开发环境使用独立 Python 3.12 虚拟环境。系统当前只有 Python 3.14，不能直接作为目标运行环境。依赖、模型和工具版本必须锁定。

模型可以在首次安装或初始化时下载，也可以手动放入模型目录；下载完成后，应用启动、解析、生成和导出都必须可以断网运行。仓库不提交大型模型文件。

## 已选方案

### 桌面应用

采用 Python 3.12、PySide6 和 SQLite 构建单进程 Windows 桌面应用，选择此方案是因为它适合本地文件处理、后台任务、项目持久化和交互式校正，同时保持最短实现链路。

本地网页应用会增加服务启动和端口管理；纯命令行工具无法提供可用的角色校正流程，因此不采用。

### 本地 TTS

首选 Kokoro-82M v1.1-zh 的 ONNX 版本，使用 `kokoro-onnx` 推理和中文 G2P。该模型体积小、支持 CPU、提供大量固定中文男女音色，并且模型为 Apache 2.0 许可。

MeloTTS 也支持本地中文和 CPU，但固定中文角色音色选择较少，不适合本项目首要的多人区分需求，因此不采用。

本地大语言模型角色推断会使安装体积、显存和调试复杂度显著增加，不作为 MVP 阻塞项。

### 角色识别

第一版采用可解释的规则管线，不全自动猜测：

1. 按段落和中文引号识别对白。
2. 从 `名字 + 说/问/道/喊/答/笑道/沉声道` 等明确模式中提取角色。
3. 处理“名字说：‘……’”和“‘……’名字说”两种常见顺序。
4. 用别名字典合并“林舟”“林师兄”等人工确认的别名。
5. 代词、连续对白和无提示对白保留低置信度或未分配状态。
6. 用户在界面中人工确认后，将结果保存到项目。

音色按角色分配，不按性别猜测自动绑定。新建角色时使用默认占位音色，并明确提示尚未分配。

## 软件结构

建议分成以下模块：

- `app/ui`：PySide6 窗口、章节/角色/片段编辑和任务进度。
- `app/domain`：章节、角色、片段、配音任务和项目状态的数据模型。
- `app/importers`：编码检测、文本清理和 TXT 分章。
- `app/parsing`：旁白/对白拆分、角色提取和置信度。
- `app/tts`：TTS 接口、Kokoro 实现、分块和音频缓存。
- `app/audio`：WAV 拼接、停顿插入和 MP3 编码。
- `app/storage`：SQLite 项目库、迁移和原子保存。
- `app/workers`：后台生成任务、取消、重试和进度信号。

UI 只通过领域服务和任务接口操作数据，不直接调用 TTS 或数据库细节。TTS 必须通过接口隔离，测试和后续更换引擎不能依赖 Kokoro 的文件格式。

## 数据与项目文件

每个小说是一个独立项目目录：

```text
项目目录/
  source.txt
  project.sqlite3
  cache/audio/<内容哈希>.wav
  exports/
  logs/app.log
```

SQLite 保存章节、文本片段、角色、别名、音色分配、片段状态和项目设置。原 TXT 复制到项目中，避免源文件移动后项目失效。数据库写入使用事务，项目设置等小型状态可采用原子替换。

音频缓存键至少包含规范化文本、TTS 模型版本、音色 ID、语速和分段参数。缓存以文件形式保存，避免数据库膨胀。

## 生成流程

1. 用户创建项目并选择 TXT。
2. 导入器检测编码、统一换行、清理不可见字符，并生成章节和片段。
3. 解析器标记片段类型、角色、角色置信度和依据文本。
4. 用户检查章节和角色、批量修正片段并分配音色。
5. 用户选择章节或整本生成。
6. 后台任务逐片段查询缓存；未命中时调用 TTS 生成 WAV。
7. 每章完成后按顺序拼接音频，在旁白、对白和段落之间插入短停顿。
8. 将章节音频编码为 MP3，并记录成功状态、文件路径和时长。
9. 失败片段记录错误并允许单独重试；取消时保留已完成结果。

长旁白按中文标点切成适合 TTS 的小段，再作为同一个片段顺序生成和拼接。单次生成不把整本书读入内存。

## 界面

MVP 使用一个主项目窗口：

- 左侧：章节列表、章节生成状态和“开始生成”入口。
- 中间：当前章节的片段列表，显示类型、说话角色、文本和识别状态；支持选择多个片段后批量分配角色。
- 右侧：角色列表、角色别名、音色选择、试听和当前章节进度。

首次打开时提供“创建项目”。项目打开后自动恢复上次章节和筛选状态。错误以可定位的提示出现，日志中保留堆栈摘要和任务上下文。

## 测试与验证

自动化测试至少覆盖：

- UTF-8、GBK、UTF-16 和混合换行导入。
- 常见章节标题、无标题长文本和空文件。
- 中文引号对白拆分，以及前置、后置说话提示。
- 未分配角色、别名合并和批量角色修改。
- 缓存命中/失效规则和失败重试状态。
- SQLite 项目保存、重新打开和 schema 迁移。
- WAV 停顿拼接、MP3 输出文件和时长。
- 使用假 TTS 引擎的端到端项目流程，测试不得依赖网络或 GPU。

人工验收使用一段包含旁白、两个角色、别名和未分配对白的中文 TXT：

1. 创建项目并确认章节、旁白、对白和角色结果。
2. 为至少两个角色分配不同音色并试听。
3. 修正一处角色归属，确认只重生成受影响片段。
4. 生成一章并成功播放 MP3。
5. 关闭应用后重新打开，确认修改和生成状态仍在。
6. 在断网状态下重复一次生成，确认功能不受影响。

## 实施边界

第一版完成后，以下增强留给后续版本：

- GPU 推理加速和性能基准。
- 本地小语言模型辅助角色消歧。
- M4B 单文件、章节元数据和移动端播放适配。
- EPUB/PDF、更多音色、音效和情绪控制。
- 正式安装程序、自动更新和发布分发。

实现者可以根据实际依赖兼容性调整 UI 库的小版本、音频编码工具和项目目录默认位置，但不能改变离线运行、可人工校正、可断点继续和分章 MP3 这四项 MVP 约束。
